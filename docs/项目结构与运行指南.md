# 项目结构与运行指南

本文档说明当前仓库的真实目录分工、运行入口和数据流向，方便后续维护时快速定位文件，不影响任何运行逻辑。

## 1. 目录分工

- [front](../front)：前端应用，负责页面、路由、图表和接口联调
- [backend-spring](../backend-spring)：后端应用，负责 REST API、数据库访问和 Spark 任务编排
- [docs](.)：项目级说明文档、集群启动指南和数据处理说明

## 2. 前端结构

前端目录中最重要的部分是：

- `src/api`：请求封装和接口类型
- `src/pages`：页面级入口
- `src/views`：业务视图组件
- `src/router`：路由配置
- `src/components`：复用组件
- `docs/API_CONTRACT.md`：前后端契约说明

前端启动方式：

```bash
cd front
npm install
npm run dev
```

## 3. 后端结构

后端目录中最重要的部分是：

- `src/main/java/com/nba/backend/controller`：HTTP 接口
- `src/main/java/com/nba/backend/service`：业务逻辑
- `src/main/java/com/nba/backend/repository`：JPA 数据访问
- `src/main/java/com/nba/backend/entity`：实体模型
- `src/main/resources/application.yml`：默认配置
- `scripts/sql`：数据库维护脚本
- `scripts/spark_nba_ml.py`：Spark 预测脚本

后端启动方式：

```bash
cd backend-spring
mvn spring-boot:run
```

默认数据源指向 `master:3306/nba_stats`，因此在本地环境中如果没有这个主机名，需要先通过环境变量覆盖数据库连接。

## 4. 数据流向

1. 用户在前端页面操作
2. 前端通过 `/api` 调用后端
3. 后端通过 JPA 读取和写入 MySQL / MariaDB
4. Spark 预测脚本从 HDFS 读取比赛数据并写回预测快照
5. SQL 脚本负责索引、回填和维度补齐

## 5. 维护顺序建议

如果你要从干净环境重新恢复项目，建议按下面顺序检查：

1. 确认数据库 schema 已初始化
2. 导入基础数据
3. 执行索引脚本
4. 执行高级指标回填脚本
5. 执行维度补齐脚本
6. 启动后端并访问 API
7. 启动前端并检查核心页面

### 5.5.6 球员数据分析页面实现

球员数据分析页面对应前端 `front/src/views/PlayerAnalysis.vue` 与 `front/src/views/Prediction.vue`。其中，`PlayerAnalysis.vue` 作为页面容器负责呈现标题“表现预测中心”，并将核心分析界面以内嵌方式交给 `Prediction.vue` 渲染；前端路由在 `front/src/router/index.ts` 中注册为 `/players`。因此，该页面的功能定位并不是简单展示球员静态信息，而是围绕单个球员完成“检索、查看、预测、解释”一体化分析，帮助用户从历史赛季表现出发，进一步观察下一场表现预测、赛季走势变化和关键影响因素。

从页面功能设计看，界面整体分为左右两个主要区域。左侧区域用于球员搜索与选择，用户可以输入姓名关键字调用搜索功能，列表中展示球员姓名、所属球队以及场均得分、篮板、助攻等基础统计，并通过“选择”按钮锁定分析对象。右侧区域在选中球员后展示基础数据概览，包括场均得分、场均篮板和场均助攻；用户点击“生成即时预测”后，页面会展示该球员下一场比赛的预测得分、预测篮板、预测助攻以及模型置信度。除此之外，页面下方还通过标签页进一步提供“赛季趋势预测”和“模型可解释性”两类深度分析能力，使球员分析不再停留于单次预测结果，而是形成短期预测与长期趋势结合的完整分析链路。

从数据交互实现看，页面主要依赖四组接口。其一，前端通过 `GET /api/players` 获取球员列表与基础统计信息，对应后端 `backend-spring/src/main/java/com/nba/backend/controller/PlayerController.java` 中的球员查询接口，核心封装逻辑位于 `backend-spring/src/main/java/com/nba/backend/service/NbaDataService.java` 的 `searchPlayers()` 方法。该方法优先结合 `fact_player_season`、`dim_player` 和 `fact_player_game` 组织球员最近赛季统计、位置与球队信息。其二，点击即时预测后，前端调用 `POST /api/prediction/player`，后端由 `PredictionController` 转入 `NbaDataService.predictPlayer()` 处理；该逻辑优先读取 `fact_player_season` 中最近赛季的场均得分、篮板和助攻数据，再生成下一场表现预测。其三，赛季趋势分析通过 `POST /api/prediction/season` 获取，实际由 `NbaDataService.predictSeasonTrend()` 调用 `playerSeasonHistory()` 读取球员历史赛季序列，并在此基础上生成未来两个赛季的趋势点。其四，模型解释能力通过 `GET /api/prediction/explain/player` 提供，底层由 `NbaDataService.explainPrediction()` 综合最近赛季得分趋势、组织能力贡献、篮板稳定性以及球队近期状态等因素，构造可解释性分析结果。上述接口协议均可在 `front/docs/API_CONTRACT.md` 中找到对应定义。

从可视化呈现方式看，该页面并未采用单一数据表输出，而是通过多种界面元素增强分析表达。即时预测结果通过数据卡片高亮展示预测得分、篮板与助攻，置信度则以进度条形式呈现，使预测强弱能够被快速感知。赛季趋势部分使用 ECharts 绘制折线图，将历史数据与预测数据放在同一坐标系中对比展示，便于观察球员能力变化趋势。模型可解释性部分则使用横向柱状图呈现各个影响因子的贡献方向和贡献大小，并通过颜色区分正向贡献和负向影响，从而提升结果解释的直观性和可读性。页面整体交互基于 Vue 3 与 Element Plus 实现，图表渲染依赖 ECharts，后端则通过 Spring Boot 提供 RESTful API 支撑数据请求。

综合来看，球员数据分析页面已经实现了从球员检索、基础数据查看、下一场表现预测到赛季趋势分析与模型解释输出的完整闭环。该实现既保证了页面交互的直观性，也使球员分析结果具备一定的预测性与解释性，能够为用户提供较为完整的球员表现分析工具。

### 5.5.7 球队数据分析页面实现

球队数据分析页面对应前端 `front/src/views/TeamComparison.vue`，前端路由在 `front/src/router/index.ts` 中注册为 `/teams`，页面标题为“球队数据对比”。该页面的主要目标是支持两支球队在同一赛季和同一分析维度下进行横向对比，帮助用户从多项核心指标上判断球队整体实力差异，而不是只查看某一支球队的单边数据。

在页面布局与功能设计方面，页面顶部首先展示已加载球队总数、东部球队数和西部球队数，用于形成整体数据概览。中部配置区提供球队 A、球队 B 选择器，并支持对比赛季和对比维度切换，其中对比维度分为综合、进攻、防守三类；同时还提供“交换球队”“随机一组”和“执行深度对比”等交互操作，提升页面使用效率。完成对比后，页面下方依次展示核心指标图表、指标明细表格、胜率进度条、深度结论卡片、指标对抗分解以及自动生成的结论速览，从而将原始数据、差值分析和文字化判断组织为一体化对比结果。

从数据接口与业务逻辑看，页面首先通过 `GET /api/teams` 获取候选球队列表，对应后端 `backend-spring/src/main/java/com/nba/backend/controller/TeamController.java` 中的球队列表接口；其封装逻辑位于 `NbaDataService.getTeams()`，当仓库连接到真实数据源时可返回球队名称、城市和分区信息。发起对比时，前端调用 `POST /api/teams/compare`，并传入球队名称、赛季和维度参数；后端再由 `TeamController` 转入 `NbaDataService.compareTeams()` 处理。当前实现中，服务层会根据请求中的球队名称、赛季和维度参数调用 `buildMetrics()` 生成两支球队的对比结果，返回指标包括得分、篮板、助攻、胜场和胜率。前端在接收到这些结果后，还会继续计算领先项、差值百分比、综合领先方以及自动化文字结论，以增强页面分析深度。相关接口字段同样在 `front/docs/API_CONTRACT.md` 中有清晰定义。

从可视化表达方式看，球队页面采用多种组件共同完成结果展示。核心指标差异通过 ECharts 柱状图进行对比，能够直观展示两支球队在得分、篮板、助攻等维度上的差异；明细数据则通过表格进行并列展示，方便用户查看具体数值。胜率信息使用进度条突出表现，进一步强化两队在赛季成绩上的对比感知。除此之外，页面还会自动生成“综合占优”“势均力敌”等结论，并将每项指标的领先方和差值拆解为独立卡片，使页面具备更强的分析表达能力。整个页面仍然采用 Vue 3 与 Element Plus 完成交互结构，由 Spring Boot 提供 RESTful 接口支撑，图表部分统一使用 ECharts 渲染。

总体而言，球队数据分析页面已经实现了球队选择、赛季筛选、维度切换、结果对比、结论提炼和差异可视化等完整流程。该页面不仅完成了球队基础数据的结构化展示，也进一步输出了可直接理解的对比结论，从而提升了球队实力分析与比赛研究场景下的交互性和可读性。
